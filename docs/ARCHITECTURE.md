# m-ui 架构

> 本文按"现在真实跑着的代码"写,不是愿景稿。每节末尾的 **实测** 指在 JP(testw.joinvip.vip)/ HK 两台真机上验证过的行为。

## 1. 目标与边界

m-ui 要解决的是一个人管两到三台入口服务器、几十到几百个订阅用户的场景:

| 需求(用户原话) | 落点 |
|---|---|
| 面板内输入域名申请证书;各机各签 | 证书页(ACME http-01 / Cloudflare dns-01),自动续期,热更新 |
| 一键开关 WARP 本地代理;vps.txt 里的优化全部进面板 | 运维页(WARP 安装/启用/停用/卸载、swap/sysctl+BBR/limits/NTP,参数可调) |
| 多服务器,只管一台;用户/出站/路由/流量/日期全同步 | Hub/Agent:主机推快照、回收账本、集中判定 |
| 入站按延迟自适应;clash 为主,Shadowrocket 多 | 订阅按服务器展开节点 + 每线路 url-test 组,客户端选延迟低的入口 |
| 定期换机,一键还原全部状态 | 单 zip 备份(库 + 证书),上传即整机还原自动重启;换机向导 |
| 单用户同时在线设备数、上下行限速 | 数据面 Limiter:按源 IP 并发计数(IPv4 地址与 IPv6 /64 各自计数,跨机并集)+ 令牌桶 |
| 角色开关:关=主,开=副 | 设置 `nodeMode` 一个布尔 |
| 从旧面板备份无缝迁移 | importer:端口/凭据/面板路径/订阅 URL 全保留 |

**不做的事**:多租户、复杂路由规则(线路上只做按域名 / IP 段 / 端口的简单分流;GeoIP、规则集分流交给客户端)、多协议链式代理、Web 终端。

一个二进制、一个 SQLite 文件、一个 systemd 单元。主副机跑同一份代码,行为差异只由 `nodeMode` 决定。

## 3. 数据模型(核心抽象)

- **Line 线路** = 入口协议 + 端口 + TLS/传输 + 上游(+ 可选的分流规则)。渲染成 sing-box 的一个 inbound 和一条 `inbound→outbound` 路由规则;有分流规则时在它前面按顺序加几条(域名 / IP 段 / 端口 → 某个上游、直连或拦截),规则指向的上游也渲染出站。端口在所有服务器上一致,所以"线路"天然就是跨机概念。
- **Upstream 上游** = 一个 sing-box outbound(WARP 就是 socks 127.0.0.1:40000)。`direct`/`block` 内置不入库。
- **User 用户** = 凭据(按协议分键,一次生成全协议可用)+ 配额/到期/周期重置/设备数/限速 + 计量;`UserLine` 决定订阅里有哪些线路。
- **Node 入口服务器** = 域名(SNI)+ 连接地址 + API 地址 + 令牌;`is_local` 标本机。连接地址留空时用这台探测到的公网 IP:IPv4、IPv6 各测一次(本机写设置 `publicIp` / `publicIp6`,副机随报告上报),按 `addr_family` 选,默认 IPv4,选的那个没有就用另一个。
- **Plan 套餐** = 上述用户字段的模板。
- **Stats** 时序桶(resource/tag/time/direction 唯一,累加合并)——天然支持多机合并。
- **AgentCounter / TrafficCursor**:副机只增不减的账本 + 主机侧游标,见 §6。
- **Setting** key/value:端口、证书路径、角色、通知、巡检、备份等一切开关。
- **Rule / LimitState** 限速规则(时段 / 突发;目标 = 全部 / 指定用户 / 指定代理名下)与生效中的规则限速。规则只在主机判定,状态随快照下发;主副机计算限速时把状态叠加到用户自己的限速上(只升不降 / 覆盖,多条取最严)。状态不进落地页。

选择 SQLite(纯 Go 驱动、WAL)的理由:单文件即全部状态,备份 = `VACUUM INTO`,换机 = 复制文件;规模(几百用户、几十线路)远在其舒适区。

## 4. 进程内组件与职责

| 包 | 职责 | 依赖方向 |
|---|---|---|
| `core` | 内嵌 sing-box:Box 生命周期、StatsTracker、ConnTracker、Limiter、入站用户热换、干跑校验、单个出入站增删 | 只依赖 sing-box |
| `render` | DB → sing-box JSON;协议特性表;TLS(cert/reality/none)与传输;上游 outbound | model |
| `runner` | 编排:渲染→启动→**三级重载**;证书签发/续期;备份/重启;首启初始化;暴露给 web/hub 的能力 | core render sub jobs monitor hub notify acme backup |
| `web` | 会话认证、CSRF 守卫、REST API、审计、内嵌前端(零构建 ES modules)、agent 接口 | runner |
| `sub` | 订阅生成(链接/clash)、落地页、订阅服务(独立端口直出 HTTPS) | render model acme |
| `jobs` | 10s 收账、10s 限速规则、1m 执法(重置/禁用/踢线,记下停用原因)、1h 清理(48h 前的分钟样本并成小时桶) | core model rules |
| `rules` | 限速规则判定(时段按面板时区;突发按每规则 × 用户的滑动窗口,用量倒退即重开窗口)、生效状态的写入 / 到期 / 审计、叠加计算 | model |
| `hub` | 主副机同步(§6) | model notify |
| `monitor` | 上游巡检、看门狗、用户预警、日报 | notify |
| `acme` / `certutil` | LE 签发、证书信息/预检、自签、TLS 热加载 | — |
| `backup` / `ops` / `notify` / `creds` / `importer` | 见名知义 | — |

依赖是单向的:`web → runner → (core, render, …)`;`runner` 通过函数注入把能力给 `jobs/monitor/hub`,避免环。

## 5. 数据面:三级重载

这是 m-ui 最重要的运行时决策——**改什么就动什么,绝不为了小改动断所有用户**:

| 变更 | 动作 | 用户连接 |
|---|---|---|
| 用户增删/启停/配额/限速/线路分配 | `ReloadUsers`:入站用户表原地热换(hy2/anytls/tuic/trojan/vless/vmess/ss),不支持热换的入站(socks/http/mixed)单独重建;被移除 / 换了凭据的用户即时断线 —— 连接和**整条会话**一起关(hy2/tuic/anytls 只在会话建立时鉴权一次,只断子连接的话客户端在同一会话里马上再开一条);表没变的入站一条会话都不动;限速/设备数策略重下发 | 不受影响(被禁用者除外) |
| 踢下线 | `KickUserAll`:本机断连接 + 关会话 + 清在线 IP,再并发派发到每台副机(每台 ≤3s,同名单飞);回 404 的副机标"版本过旧" | 只有被踢的用户 |
| 上游增删改、测试 | `ReloadUpstreams`:对比上次应用的出站集合,只对变化的 tag 做 Remove/Add | 不受影响 |
| 线路增删改、线路换上游、证书更换 | `ReloadAll`:先 `ValidateConfig` 干跑新配置,通过才 Stop/Start | 断开一次 |

保存前还有一道 **整配置干跑**:任何线路/上游写入都在事务里渲染整套配置并用 sing-box 初始化一遍,不通过就回滚。这是从真机事故学来的:一条缺 PSK 的 ss2022 线路曾让之后每一次重载都失败。

**实测**:JP 上改上游数据面 uptime 不归零;经 HK 副机 hy2 入站 57ms、ss2022 61ms、经 WARP 16ms。

## 6. 多机同步(Hub ↔ Agent)

- **推**:主机每 5s 在一个只读事务里构造快照(线路/上游/用户(去掉计量)/用户线路/入口/少量订阅设置/落地页 logo)并算修订号,修订号没变就不碰写锁;与上次推送不同(或超 10 分钟)就 `POST /api/agent/apply`。每个修订只编码一次、各台共用;报过 `applyGzip` 的副机收 gzip 压缩的请求体(老副机照旧收不压缩的),同时推整份快照的最多 3 台,等确认的时限按快照大小放宽(25s + 每 MB 2s,封顶 5 分钟)。等确认超时了就看同一轮的报告:副机已经在这个修订上、没有待重载就记为已推送,否则退避。副机整表替换(保留自己的账本),按变化类型走三级重载;同一修订同一序号、而且是本版程序完整应用过的(`hubAppliedBy` 记着「程序版本#修订#序号」)、落地页 logo 也和快照一致的直接确认,不再重写 —— 旧版程序收快照时会丢掉自己不认识的字段(比如 logo)、修订号却照记,升级后的第一份要整份应用一次。主机从报告里看到副机换了版本,下一轮就重推一次(不等 10 分钟的定期重推,也不等之前的退避)。
- **拉**:同一轮 `GET /api/agent/report` 拿到副机的单调账本、在线 IP、运行状态、证书剩余天数。网络部分做完就放开这台的闸,报告交给唯一的并账协程(每台只留最新一份)。主机按 `TrafficCursor` 只计增量:没变化的计数器不碰写锁,有变化的每 1000 个一笔短事务;计数器变小时,同名用户删了又建(游标记下的用户 id / 建号时间对不上)从 0 计,同一个用户变小按账本回退处理(游标对齐、这一次不计、告警)。增量写入用户与 `Stats`(resource=user 与 resource=node)。已删副机在途的报告整份丢弃。
- **下线**:停用 / 删除副机时给它推空用户表;没送到的落库(`node_decommissions`),每轮重试直到它确认。
- **判定只在主机**:副机 `jobs` 不执法。主机禁用用户 → 快照变化 → 5s 内推到副机 → 副机热换用户表踢线(连接与整条会话一起关)。面板的「踢下线」另走 `POST /api/agent/kick` 即时派发到各副机,不等快照。
- **升级内核必须核对**:`core/protocol/usersess` 的会话登记靠 sing-quic 的 `qtls.ServerConfig` 扩展点(`ListenWithOptions` / `ListenEarlyWithOptions` / `ConfigureHTTP3` 对 TLS 配置做类型断言)接管 QUIC 监听,`usersess/quic.go` 里复制了 sing-quic 默认路径的 Transport 参数(hy2 无混淆时的 StatelessResetKey、有混淆时关版本协商包、`SetSingleUse`)。升 sing-box / sing-quic / quic-go 时逐项对照上游 `qtls` 与 `hysteria2/service.go`、`tuic/service.go`,参数变了这里要跟着改;换表 / 踢线等被关的 QUIC 连接真正断开才返回,靠的是 quic-go 在事件循环断开全部流、发出 CONNECTION_CLOSE 之后才取消 `conn.Context()`,这个语义变了会话会在"已断开"之后还通一阵。`usersess` 的单测与 `M_UI_E2E=1` 的真实入站测试(`core/usersess_e2e_test.go`)都要过。另有两处靠 sing-quic 的行为认出"到了但认证没过"(见 `core/protocol/arrival`):hysteria2 密码不对时把认证请求(`POST https://hysteria/auth`)交给伪装站点 —— 入站在伪装站点外面包了一层认它;tuic 认证失败 / 超时用 `CloseWithError(0, "")` 关连接 —— 会话登记表在连接结束时认"从没开过流、本端关的"。升级后 `core/arrival_e2e_test.go` 要过。
- **老连接的设备数**:limiter 对空闲后恢复的 IP 重新执行设备上限;副机上报超过 300 秒没刷新的在线 IP 不再计入并集(失联副机的名单不能拿来拒新设备、断老连接)。
- **设备数跨机**:主机把"其他机器上在线的 IP"下发给每台机器的 Limiter;本机计数 = 本机活跃 IP ∪ 外部 IP,同一 IP 切换入口不占新名额。
- **失联**:>60s 拉不到报告告警一次,恢复再告警一次;副机离线期间主机照常工作,副机继续用最后一份配置服务用户(只是账本回收延后)。

鉴权:`X-Agent-Token` 常量时间比对,非副机角色一律 403;传输建议 HTTPS(副机自签时主机可选跳过校验)。

**实测**:配对 → 3 线路/用户推送 → 禁用传播 → 副机流量回收到主机(up/down 增量)→ 主机看到副机上的在线 IP。

## 6.5 主机容灾与设为主机(`ha` 包)

只有两个概念:**设为主机**(计划内把主机换到一台副机)和**主机容灾**(主机失联时由**备用**接任)。没开过主机容灾、也没换过主机的集群(纪元为 0)主副机的请求、推送内容、修订号和以前完全一样。

- **纪元(epoch)防脑裂**:每台在本机设置里存 `haEpoch`;每次接任或设为主机加一。主机发往副机的每个请求带 `X-HA-Epoch` / `X-HA-Master`(在 `hub.do` 里统一加),副机在 agent 鉴权里按 令牌 → 纪元 → 副机模式 判:纪元低或同纪元换了主机 → 409 `stale_epoch`;纪元高时只有 `apply` / `ha/state` 能让副机升纪元,且要满足其一:投过票、收到过交接标记、对现主机的租约(120 秒)已过期、本机是回来后变成副机的原主机、本机还没进过纪元;否则 409 `still_following`(还联系得上原主机的副机不换主)。主机收到过半(认得纪元的)副机回 stale,或启动自检(跑主机任务之前问一圈)就发现更高纪元,就变为副机:留备份、`nodeMode=true`、换一本流量账本、重启。只有少数副机这么说时不变,告警"已脱离";多数副机一直还跟着另一台活着的主机、自己又没有多数时让出;有多数的主机看到"跟过已经不在的主机"的副机(租约过期)以更高纪元收回(先发交接标记)。
- **容灾状态**(`POST agent/ha/state`):纪元、主机签名公钥、备用名单、阈值、暂停到何时、见证要测的地址、集群密钥、交接标记;给备用的还带封在它公钥下的通知设置与"副本截至"。很小,变了才推,不进快照修订号。
- **备用的数据副本**:按服务器顺序取前 N 台合格的副机(启用、5 分钟内在线、版本够、报过公钥且没变、磁盘够)。主机在只读事务里按列原样拷表(不走 JSON、不走 gorm Create,`json:"-"` 的令牌与密码、停用状态都保留;不带会话、时序、订阅日志、账本,审计只带 7 天),主机身份(订阅域名 / 端口 / 路径 / 证书、作为副机时怎么连)记在 meta,zip 后用随机数据密钥分块 ChaCha20-Poly1305 加密,数据密钥用 nacl/box 封给备用的 X25519 公钥(首次见到时钉住),ed25519 签名。备用单写者写独立文件(`<数据目录>/ha/replica.cur|prev`,0600,两代),不碰库;每天解开跑 `integrity_check`。内容没变不重发。
- **接任**(`Takeover`):先把纪元加一、角色记成 promoting;解开副本,把本机还没上报的账本按副本里的游标并进去(副机流量靠单调账本 + 游标自愈),换上本机的本机设置与证书库,套用原主机身份,本机那行标"本机",原主机那行填上怎么连它并先停用(不进订阅),写成 `<库>.promote`;下次启动还没打开库时 `ha.ApplyPending` 换上(旧库留作 `.pre-promote-<时间>`)。之后它就是主机(没有临时状态),发通知、按设置改 DNS;原主机回来认了新纪元后,新主机重新启用它那一行。
- **设为主机**(`SetMaster`,原主机发起):冻结写操作(面板、外部 API、代理面板、Telegram 机器人的写一律 503,超时自动解冻)→ `agent/ha/prepare` 拿目标的一次性 X25519 公钥(经现有链接:令牌 + 钉住的证书指纹;明文 http 时被动窃听者也解不开)→ 整库(只不带会话、账本)+ 身份加密签名推到 `agent/ha/handover`,目标验证、组好新库暂存 → 给副机推交接标记(纪元 E+1 的主机是目标)→ `agent/ha/commit` 目标换库重启 → 原主机变为副机(带交接标记,目标一推就跟)。提交没回话时问 `agent/ha/incoming`;问不到就保持冻结直到超时,目标若已接手,多数副机会对原主机回 stale,它照常变为副机。
- **失联判定**(`engine`,备用每 10 秒):租约 60 秒以上 → 经 `/api/ha/peer/status`(集群密钥 HMAC 签请求与响应,±10 分钟,限流)问其它副机还联系不联系得上主机;Globalping 境外测点 TCP 连主机公网 IP(≥2/3 通 = up,≤1/3 = down);排在前面的备用还在就让它;确认模式到时间发带码的 Telegram(只在等确认时长轮询,409 当作主机机器人还活着的证据),自动模式三台以上要过半票(`/api/ha/peer/vote`,先落库再回票),两台要见证 down。主机升级、计划内重启前把暂停推给备用。
- **命令行** `m-ui ha …` 经库里的 `haCmd` / `haCmdResult` 交给运行中的服务;要 root。

## 7. 订阅

- 入口列表来自 `nodes` 表:多入口时每条线路按入口各出一个节点,名字加 `-入口名` 后缀;单入口不加。
- **节点地址默认是服务器 IP,域名只作 SNI**(设置 `subServerAddr` 可改为域名):大陆客户端本地 DNS 常被污染,Shadowrocket 这类在本机解析域名的客户端会直接超时,而走远程解析的客户端(nextin)不受影响——给 IP 两边都稳,TLS 靠 SNI 照常校验。每台服务器的公网 IP 由本机探测(主机)或随报告上报(副机),也可在服务器页手填。
- 每台服务器有**流量倍率**:经它的流量按倍率计入用户用量(主机本机在收账时乘,副机账本回收时乘,游标记原始值),节点名带 `x2` 标记。
- 线路可选**部署到哪些服务器**(`NodeIds`,空=全部):渲染只含本机应部署的线路,订阅只出对应入口。
- **外部节点**:分享链接或外部订阅 URL,主机定期抓取(先以 Clash Meta 身份要全量,内容里没有节点才换通用身份,抓取失败保留旧缓存;base64 / 明文链接 / clash YAML / sing-box JSON 都能解析成统一的节点列表,每个节点同时带名字、指纹、分享链接与 clash 代理;隐藏 / 改名按名字 + 指纹记,在服务端合并保存;面板里可展开看节点明细、逐台服务器测速(Clash 直接转 sing-box 出站)、勾选后添加为上游),分配给用户后追加在本站节点之后、进 Proxy/Auto 组;缓存随快照下发副机,副机订阅口同样可用。
- clash:多入口时每条线路生成 `url-test` 组,`Proxy` 选择组列线路组;`Auto` 覆盖全部。这就是"入站自适应":选择在客户端完成,不需要服务端探测用户延迟。
- 链接订阅:hy2/anytls/ss 与旧面板输出字节级一致(黄金测试),其余协议按 v2ray 风格参数。
- 自签证书(纯 IP)自动带 `insecure`/`skip-cert-verify`,Reality 除外;纯 IP 入口不发 SNI。
- 订阅页开着时(默认;主面板与每个代理各有开关),浏览器打开订阅地址得到落地页(用量/到期/一键导入/二维码);客户端 UA 得到原始订阅。订阅页关掉后浏览器和客户端一样。共享令牌在浏览器里得到精简版落地页(不含本人的用量、到期与用量图,也不能生成 / 取消共享)。
- 落地页 logo 存在 `page_logos` 表(主面板 reseller_id = 0 一张,每个代理一张;代理没传用主面板的,都没传就内联内置 SVG),页面用相对地址 `./<地址>/logo?v=<摘要>` 引用,共享页里的地址段是共享令牌。服务端只存解码校验过的 PNG / JPEG / GIF(≤ 64 KB、≤ 1024×1024;SVG / WebP 由浏览器先用 canvas 转成 PNG),输出带 `nosniff`、`CSP: sandbox`、`CORP: same-origin` 与按摘要的 ETag;随快照下发副机(修订号只看摘要;只带主面板与现存代理的;副机整表替换,旧版主机不发 = 一张都没有),随 `VACUUM INTO` 进备份。代理上传时在同一个写事务里确认代理还在,删代理时连同没主的行一起删。落地页深色模式下给上传的 logo 垫浅色底。
- 公告与联系方式经 `linkify`(`sub/linkify.go`)输出,是落地页上唯一把用户文案变成 HTML 的地方:文字全部转义,只有 `文字(链接)`、`[文字](链接)`(两种都认全角括号)、Tg / WhatsApp 关键词(只认 ASCII 字母)与裸 http(s) 地址变成链接,所有地址(包括关键词拼出来的)都过 `safeHref`:协议只放行 http / https / tg / mailto / tel、整段可打印 ASCII;链接不带样式(字号跟随段落)。`文字(链接)` 往回取文字时不越过前面自动识别出的地址、@用户名、号码。

## 8. 证书、备份与重启

- 证书文件路径固定在设置里;面板与订阅服务用 `GetCertificate` 每 5s 检查文件变化,续期不重启;数据面的入站由 sing-box 自己监听证书文件,续期后自动换,不重启、连接不断。只有证书**路径**变了(换成另一对文件)才走整体重载。续期检查在启动 3 分钟后先跑一次,之后每小时一次;每张证书在有效期最后三分之一(最多 30 天)开始续,结果(上次尝试、失败原因、连续失败次数、下次重试时间)写回证书库那一行,失败按 1、2、4 小时退避(最长 6 小时),通知去重落库,重启不丢也不重复。副机的续期状态随报告上来,主机代发告警。
- 备份 = `VACUUM INTO` 一致快照 + 设置引用的证书文件 + meta.json 打 zip。还原分两步:落到 `<db>.restore`,进程原地 `exec` 自身,启动时原子替换(旧库保留 `.bak-时间`)。证书:数据目录里的写回原路径(原子改名,不顺着符号链接写);数据目录外的本机那里有能接着用的(现在有效、写着备份那张的全部域名、不比备份旧或还剩两周以上、和私钥配得上:新机上先用 certbot 签好的照样接着用)就继续用,否则放进 `<数据目录>/cert/restored/`,设置与证书库改指过去(备份那一刻的副本,没有谁续:证书页与提醒按「还原的副本」处理,剩 30 天起提醒,`CertBrief.Restored` 报给主机);还原结果里放进数据目录的副本、还缺的、没写成的写进 `<数据目录>/restore-notice.json`,面板顶部提示一次,点「知道了」删掉;`meta.json` 里的路径是不可信输入,数据目录外一个文件都不写。`m-ui restore` 与启动日志逐个说清去向(`backup.Report`)。Linux 用 `syscall.Exec`,不依赖 systemd 的 Restart 策略。
- 前端资源按内容哈希打 ETag,升级后浏览器立即拿到新文件。

## 9. 安全模型

- 面板:bcrypt 密码、HttpOnly cookie、同 IP 10 分钟 5 次失败告警;写请求校验 `Sec-Fetch-Site`/`Origin` 防 CSRF。
- 两步验证:RFC 6238 TOTP(`totp` 包,SHA-1 / 6 位 / 30 s,±1 步容差);密码正确后才要求验证码,不泄露是否开启;同一时间步的验证码只能用一次(防重放);密钥暂存内存,认证器验证一次成功后才写入 `totpEnabled/totpSecret`;CLI 菜单可关闭,CLI 重置密码时一并清除(手机丢失兜底)。
- 外部 API(`/api/v1/*`):独立于会话的 Bearer 令牌(64 位十六进制,常量时间比对),`apiEnabled` 关闭即全部 401;写操作审计记为 `api`。令牌与 2FA 设置不随主副机同步。
- 主副机:令牌 + 常量时间比对;快照不含令牌与计量。
- 主机容灾:数据副本只给备用,用它的公钥端到端加密、主机签名,不进它的库与备份;设为主机的整库数据用目标的一次性公钥加密。副机之间的同伴接口只认集群密钥 HMAC(停用 / 删除副机时轮换)。设为主机、接任、改主机容灾都要登录的管理员再输一次密码(开了两步验证加动态码),代理与外部 API 令牌触发不了,命令行要 root;`ha` 开头的设置一律不经设置接口发给浏览器,密钥、令牌不进日志与通知。
- 备份文件含用户凭据与证书私钥——下载/推送 Telegram 前要知道这一点。
- 运维脚本是固定模板,只接受校验后的数字与 `key=value` 行。

## 9.5 诊断

- 概览"最近入站连接":数据面的连接跟踪器在每次入站连接通过握手与认证、被路由时记一笔(源 IP × 线路,带认证到的用户),被设备数 / 代理设备池拒绝的也记并标出原因,不扫日志。"到了但没过握手 / 认证"另存一份(`core/protocol/arrival`):trojan / vless / vmess / anytls 的 TLS(含 REALITY)握手失败、协议认证失败,hysteria2 / tuic 的认证失败;连上就断、被重置、超时的不记(端口扫描、TCP 连通探测,包括面板自己的大陆连通 / IPv6 入站检测)。REALITY 把没过认证的连接整条转给伪装目标、错误一律是 `processed invalid connection`,看不出对端发没发东西,所以 REALITY 入站握手前套一层只看第一个字节(`arrival.Watch`,对 sing 的拆包透明):一个字节没收到、或第一个字节不是 TLS 记录(0x16)的不记,收到 TLS 记录还没过的照记,伪装目标连不上的照记。独立上限 100 个来源、新来源按令牌桶限频,扫描刷不掉正常记录;只记,不改放行判定;副机随报告上报(`connFails`,新版同时带 `connFailsOk`,老副机不带,主机据此在服务器状态里标 `noConnFails`)。主机汇总时按服务器公平取(超过上限时每台先留自己最近的一条,其余按时间补满;不严格轮流,跟踪器只按条数淘汰,安静的服务器上几天前的旧记录不能挤掉忙的那台刚来的连接),每条带 `nodeId` 与来源地址族 `family`;概览两张表只显示前几行,截断时同样这么取(`web/assets/js/fair.js` 的 `shownConns`,页面只渲染;后端只在超过接口上限时才筛)。客户端"连不上"先看它:在通过认证的列表里 = 连上了;在"到了但没过"里 = 证书 / SNI / REALITY 参数 / 密码不对(或用户已停用、到期、超量,凭据已撤下)。两处都没有 ≠ 包没到:不记的有 hysteria2 / tuic 的 QUIC 握手失败(证书、SNI / ALPN)与 hysteria2 混淆密码不对、REALITY 线路上连上就断或不是 TLS 的连接、ws / grpc 等传输层里的 TLS 失败、shadowsocks / socks / http / mixed 线路、不上报的老副机;最准的是在服务器上抓包。
- 大陆连通检测(`reach/`)按地址族选端口:订阅里走 IPv6 的线路(含自定义地址写成这台自己 IPv6 的:等于手填的连接地址或探测到的公网 IPv6;中转、CDN 之类别处的 IPv6 写了 `node_id` 也按 IPv4 一侧算,端口照样测这台的 IPv4,不让这台变成 `noPort`)不拿来测 IPv4 地址;副机的线路在订阅里都不走 IPv4 时这一项不测,记 `noPort`(无可测端口:灰色、不告警,算结论,盖掉以前的"被墙");主机照测订阅地址的 IPv4 和订阅端口(`Runner.subAddrIPv4`:订阅地址 `Runner.PublicHost` 是用户刷新订阅的入口,它的 IPv4 被墙要告警;是域名时在主机上查 A 记录,有这台自己的 IPv4 就测它、没有就测解析出来的最小那个,解析超时之类说不准时退回测这台的 IPv4),订阅地址是 IPv6 字面量、或是没有 A 记录的域名时才记 `noPort`;服务器根本没有 IPv4(只上报了 IPv6,连接地址、域名也解析不到 IPv4)时不论线路是否走中转、订阅是否给域名,主机副机都记 `noPort`(不记成没测成,否则以前的"被墙"永远清不掉),解析域名出错(不是"没有记录")时算没测成;走 IPv4 的只有 UDP 线路时借订阅 / 面板 API 端口看 IP 有没有被墙,API 端口连香港也连不上同样记 `noPort`(多半只对主机放行)。有走 IPv6 的线路的服务器,同一轮再从境外支持 IPv6 的测点 TCP 连它订阅里的 IPv6 地址(或自定义地址里写成这台自己 IPv6 的那个)+ 第一条走 IPv6 的 TCP 线路端口(目标是 IPv6 地址时 Globalping 只派支持 IPv6 的测点)。额度先保大陆检测:一台做完大陆检测时剩下的额度扣掉还没做完的那几台不够,IPv6 入站就等这一轮大陆检测都做完再测(放行时预留;额度缓存同一窗口里只减不增,并发时后到的旧响应不会把额度加回去)。没有可用测点和没测成一样,不盖掉上一次的结论。线路页按线路给结论:被测的那条线路显示通 / 不通,别的 TCP 线路标"未测到此端口",UDP 线路标"未测(UDP)"。主机的 `status.v6Bad` 列出 IPv6 入站不通(只算 down)的服务器,不并进 `reachBad`。不比对网卡:Azure 这类 1:1 NAT 的公网 IPv6 不在网卡上,入站却可用。UDP 线路测不了,注明抓包确认。
- 入站监听 `::`(Go 对通配地址开 `IPV6_V6ONLY=0`,双栈,不受 `net.ipv6.bindv6only` 影响);没有 `/proc/net/if_inet6`(内核关了 IPv6)时改听 `0.0.0.0`,常规机器的配置逐字节不变。
- 已知上游限制:hysteria2 开了混淆(salamander / gecko)时 UDP 套接字被包了一层,quic-go 拿不到 PKTINFO,多地址的 IPv6 主机上回包可能用错源地址。
- 重载失败不再静默:最近一次重载的结果挂在 `/api/status`,失败时页面顶部常驻提示并可一键重试;副机的重载结果随报告回主机,服务器页标出。`/api/health`(只认本机回环)给升级脚本判断"线路有入站在跑"。
- 防护:数据面默认拒绝用户访问私网地址(`allowPrivate` 可放行);订阅端口按来源 IP 令牌桶限流(`subRateLimit`,默认 120/分钟),对不上任何人的地址按 IP 聚合记一条访问日志,扫描器刷不爆表。
- 上游巡检、副机状态、证书剩余天数、公网 IP 探测都在面板上可见;审计日志记录每一次改动的操作者。

## 10. 失败模式与对策

| 场景 | 行为 |
|---|---|
| 新配置有错 | 保存被拒(整配置干跑);即使漏网,`ReloadAll` 干跑不过就保持旧数据面 |
| 证书未就绪 | 数据面启动失败但面板/订阅继续,方便在面板里解决 |
| 副机失联 | 主机照常,副机用旧配置继续服务,恢复后自动追平 |
| 主机失联 | 开着主机容灾:备用按多方证据判定后接任(确认或自动),副机流量按游标补回;没开:副机照常服务,等人处理 |
| 原主机回来 / 从旧备份还原回来 | 启动自检或第一轮推送发现多数副机已跟随更高纪元 → 变为副机(留备份),新主机把它当副机接上 |
| 设为主机中途失败 | 自动取消、解冻,目标丢掉暂存;提交结果不明时等冻结超时,纪元规则保证不会两台同时生效 |
| 副机重装 / 从备份还原 | 账本纪元换新,只建基线,不重复计 |
| 副机断电、快照回滚(账本小幅回退) | 按回退处理:游标对齐,不把整段历史再记一遍 |
| 进程重启 | 所有状态在 SQLite;WAL 每 10 分钟检查点,备份随时可复制 |
| 升级 | 换二进制重启;ETag 让前端不缓存旧模块;数据库自动迁移 |

## 11. 已知边界与下一步

- 线路(入站/路由)变化仍需整体重启:sing-box 的路由规则不能运行时改;线路改动本来就低频。新配置起不来回滚、或在冷却期里时,运行中配置里没有的线路不会被热更新补建出来(它的上游和分流规则不在旧配置的路由里),等整份配置能启动时一起上线。
- 设备数的"跨机"依赖 5s 同步周期,极端情况下两机各放行一台后再收敛。
- 停用有三种原因(手动 / 超量 / 到期):自动停用的在重置或续期后自动恢复;手动停用的不会因重置流量、「延长到期」或周期重置恢复,但套用套餐(续费 / 延期 / 换套餐,含外部 API)一律启用,面板执行前提示;代理额度用尽或到期时代理名下的用户不改启停,只在渲染与订阅处拦下(`depleted` 标记)。
- 会话落库(`sessions` 表,内存缓存),进程重启不掉线;快照带版本号,副机版本低于主机要求的最低版本时拒绝应用并在服务器页标出;有线路用了分流规则时最低版本抬到 0.6.14(不抬的话旧副机会悄悄丢掉规则),没用时不抬。
- 限速改动对在线连接立刻生效:限速器里连接持有的是用户条目,桶原地改速率或置空,不用重连;每条认证过的连接都包装(以后被规则限速也要立刻变慢)。
- 规则限速:主机每 10 秒判一轮;突发窗口只在内存(进程重启后从空开始,跨过重启那一刻的突发可能漏判一次);副机按到期时间自行解除,主机失联也不会一直限着;副机最低版本 0.6.0。
- 尚未做:更多入站协议(Naive/ShadowTLS)、外部 API 的分页、代理面板自建规则(规则表已预留归属字段)。

## 数据面日志与磁盘(v0.6.8)

真机排查过一次"隧道偶尔卡几秒、面板偶尔卡几秒":副机的数据面按 info 逐条记连接,一小时几万行经 stderr 进 journald(Ubuntu 上 rsyslog 再抄一份到 /var/log/syslog),journald 堆到几 GB;sing-box 的日志是在处理连接的 goroutine 里同步写的,磁盘一顿(`/proc/pressure/io` 的 full 停顿占到每分钟 5% 以上),所有连接跟着顿。主机那边则是 SQLite 每次提交都 fsync、加上每 10 分钟一次 `wal_checkpoint(TRUNCATE)` 独占,盘慢时面板请求要等。

- `core/log.go`:数据面日志进有界队列(8192 条),单独一个 goroutine 往外写;内核那头只入队,满了丢、丢了多少每分钟报一次。
- 数据面默认级别 warn;日志页可调 warn / info / debug / error(设置 `coreLogLevel`),运行时生效不重启;关掉记录仍是 panic。
- SQLite:WAL + `synchronous=NORMAL`(提交不再等 WAL fsync,断电最多丢最近几笔,库不会坏);定时检查点改 PASSIVE(不阻塞),TRUNCATE 只留给备份和停机。
