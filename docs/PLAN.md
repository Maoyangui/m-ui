# m-ui 实施计划

内嵌 sing-box 的多服务器代理面板,替代 s-ui + Flask + nginx 三件套。为"一人管理、双入口(HK/TW)、定期换机"的实际业务量身定制。

## 设计铁律

1. 所有状态存单一 `m-ui.db`(SQLite,纯 Go 驱动无 CGO)——备份一个文件 = 备份一切。
2. 主/副角色由设置开关决定:`nodeMode` 关 = 主(HK,完整面板);开 = 副(TW,极简页 + 配对令牌,配额判定停用)。双向切换都有护栏确认;副→主即灾备提升。
3. 单向写:管理操作只在主面板。副机是无状态数据面,配置由主渲染整份下发。
4. 流量回收用"副机单调账本 + 主端游标快照",重复拉取/断网重连/换机重装都不重复计不漏计。
5. 证书固定路径,各机自签自续(Go 原生 ACME + HTTP-01,DNS 预检)。
6. 运维动作(WARP/系统优化)是编译进二进制的固化流程,无任意命令执行。
7. 割接保端口、保凭据、保订阅 URL、保节点名——现有用户零感知,可回滚。

## 核心模型

- **线路(Line)**= 入站 + 路由规则合并:名称/协议(hy2|anytls|ss)/端口(全服务器一致)/上游/排序/开关。
- **上游(Upstream)**= 落地出站(tuic/ss/socks/…,warp 即 socks 127.0.0.1:40000)。
- **服务器(Node)**= 入口:域名/管理地址/令牌/证书/WARP 状态;IsLocal 标记主机。
- **用户(User)**= 配额/到期/月重置/凭据/线路集合/**设备数上限(按源 IP)**/**限速(Mbps,上下行令牌桶,全连接共享)**。

## 里程碑

| 阶段 | 内容 | 状态 |
|---|---|---|
| P0 | 骨架 + 数据模型 + 旧 s-ui.db 导入器(id/端口/凭据全保留)+ GitHub 仓库/构建 | ✅ |
| P1 | 数据面:内嵌 sing-box(hy2/anytls/ss 用户热更新)+ 配置渲染器 + 流量/连接追踪 + 限速/设备数本机拦截 | |
| P2 | 面板 UI(登录/仪表盘/线路/上游/用户/服务器/设置)+ 订阅输出(链接+clash、排序、提示节点、访问日志、直出 HTTPS 2056)→ 与现网输出黄金对比 | |
| P3 | 证书页(ACME+自动续期+DNS 预检)+ 运维页(WARP 开关、系统优化)+ 自动备份 | |
| P4 | 副机接入(配对令牌)+ 配置下发 + 流量回收 + 集中配额判定/禁用秒踢 + 设备数跨机聚合 | |
| P5 | 双入口自适应:clash 每线路 url-test 组(HK/TW 按延迟自动切换)+ 负载排序兜底 | |
| P6 | 一键换机向导(换副机/换主机两条流程)+ 实弹演练 | |
| 割接 | HK 并行部署 → 导入 → 黄金对比 → 停 s-ui 换 m-ui → 验证(回滚 = 重启 s-ui) | |
