用 m-ui 备份与换机

m-ui 把一切放在一个 SQLite 文件和一个证书目录里,所以备份是一个 zip,换机就是"把那个 zip 在别处还原"。这篇讲怎么做这两件事;订阅地址用的是域名时,任何用户都不用重新导入什么。

备份里有什么

  • 数据库,先做检查点把 WAL 并回去,副本是一致的:线路、上游、带凭据的用户、套餐、代理、服务器、设置、统计。
  • 证书文件:你签发或自签的证书与私钥,还原后 TLS 照常工作。

里面没有 m-ui 程序本身(安装脚本负责),也没有 /etc/m-ui 之外的任何东西。所以备份很小 —— 通常几 MB —— 而且跨架构可用。

做一份

备份 → 下载立刻拿到 zip。定时备份每天在你按面板时区选的钟点跑,按数量轮转,还可以推送到 Telegram,让一份副本活在服务器之外。文件按仅属主可读创建;它包含所有用户的凭据,请按此对待。

还原

两种方式,结果一样:

  1. 在面板里:备份 → 还原,上传 zip。m-ui 先检查它、显示里面有什么,然后换入数据库与证书并自行重启。
  2. 用安装脚本:新服务器上还没有脚本,把备份 zip 传上去后直接执行一键安装命令并带上 --restore,一步装好并还原 —— 旧面板已经没了的时候很有用:
    bash <(curl -fsSL https://raw.githubusercontent.com/Maoyangui/m-ui/main/deploy/install.sh) --restore /root/m-ui-备份.zip
    (换成你的备份文件路径;不是 root 用户时用 curl -fsSL https://raw.githubusercontent.com/Maoyangui/m-ui/main/deploy/install.sh | sudo bash -s -- --restore /root/m-ui-备份.zip。)

两种方式都是原子的:新库校验并复制到位之后,旧库才被替换。

搬到新服务器

顺序很重要,因为订阅指向一个名字或地址,而客户端会缓存它:

  1. 在新服务器上装 m-ui 并还原最新备份。端口、面板路径、凭据现在和旧服务器完全一样;订阅地址用域名的话也一样。
  2. 打开新面板看概览:数据面在跑、线路在监听、用户都在。备份页的换机向导带你逐项走一遍。
  3. 用域名的话,把域名解析切到新服务器。向导可以查各大公共解析器,让你看着生效。用 IP 的话就没法无感切换:订阅地址里写的是旧服务器的 IP,客户端刷新时连的还是旧机(旧机关了就拉不到),拿不到新地址。要把新的订阅地址(新 IP)发给每个用户重新导入;想以后换机不打扰用户,先给面板和订阅配一个域名。
  4. 副机什么都不用动:是主机去联系它们,不是反过来;它们的令牌随数据库一起过来了。
  5. 流量切过去之后关掉旧服务器。用域名的话客户端上什么都没变:同样的凭据、同样的端口、同样的订阅链接。

容易忘的

  • 新服务器的防火墙放行同样的端口:面板、订阅服务、每条线路,以及 Hysteria2 / TUIC 的 UDP。
  • 证书是给域名签的,在新服务器上原样可用;是给旧 IP 自签的,在新机上再自签一次。
  • WARP 是按服务器安装的,不在备份里。用过的话在运维页重新跑一遍。
  • 旧服务器的最后一份备份先留着,盯新机跑一天再删。

如果是从旧面板过来

那是另一个工具:导入器读兼容格式的旧面板数据库,把入站映射成线路、出站映射成上游、客户端映射成用户,保留端口与凭据。安装时加 --import 旧面板.db,或者只搬用户用 用户 → 从旧面板导入;报告会告诉你映射了什么、跳过了什么。
