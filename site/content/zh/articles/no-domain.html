没有域名也能跑 m-ui

很多人的代理跑在一台下个月就会换掉的 VPS 上,从没为它买过域名。m-ui 把这当成正常配置,不是降级配置。

到底什么需要域名

只有两样:公共 CA 签发的证书(Let's Encrypt 验证的是名字,不是地址),以及换服务器也不变的订阅地址。其余的 —— TLS 本身、Hysteria2、AnyTLS、Trojan、面板、落地页 —— 在 IP 上都能用。

第一步:自签

证书 → 自签给服务器 IP(以及你填的任何名字)生成一张长期有效的证书并装给数据面。一键完成。概览页的快速开始把它算作"证书已就绪";域名列在可选项里。

第二步:订阅怎么告诉客户端

证书是自签的时,m-ui 会给订阅里每个带 TLS 的节点加上标记,客户端不会拒绝它:Clash / Mihomo YAML 里的 skip-cert-verify: true、sing-box JSON 里的 "insecure": true,以及各通用链接格式各自的不安全标记。用户导入链接就能连,不用手动调。

代价是真实的,值得说清:关掉证书验证后,客户端无法识别出示另一张自签证书的中间人。个人用大多可以接受;对外销售的服务,域名加正式证书是更好的默认。

第三步(可选):Reality 不需要证书

VLESS + Reality 借用一个真实网站的 TLS 握手,从不出示你的证书,所以它是最干净的无域名协议:没有自签警告,没有不安全标记。快速添加 → VLESS + Reality,生成密钥对,选一个握手目标,完事。很多人在纯 IP 服务器上跑 Reality,旁边再放一条自签证书的 Hysteria2。

第四步:订阅里的地址

没有域名时,节点用服务器的公网 IP 对外(自动探测,或你在服务器上填的地址)。以后换了 IP,改一次服务器地址,所有订阅在客户端下次刷新时更新 —— 这是域名本可以省掉的唯一一步。

以后加域名

  1. 把域名解析到服务器。
  2. 证书 → 签发,HTTP-01(80 端口可达)或 Cloudflare DNS-01(API Token,不用开 80)。m-ui 开始前会预检 DNS 和端口。
  3. 在服务器页给这台机器填上域名。订阅下次刷新时从 IP 换成域名并去掉不安全标记;既有客户端不断线,因为换证书是热更新。

没有域名的副机

每台副机各自签发证书,自签就行:主机带着你的 TLS 设置推送线路,每台副机的订阅条目按该机的证书决定带不带不安全标记。主机有域名、副机只有 IP的混搭很常见。
