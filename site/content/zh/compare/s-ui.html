m-ui 与 s-ui

两个都是 sing-box 面板,都是 GPL-3.0,都是单人维护、带网页界面。如果你已经了解 s-ui,这页只回答一个问题:什么情况下 m-ui 更合适,什么情况下不是?事实于 2026-09-05 对照 s-ui 的 README 与 Releases(v1.6.0,2026-09-01)核对;s-ui 没写明的一律标 未知。

一段话版本

s-ui 是成熟的 sing-box 面板:近 1 万 star、多年发布记录、协议列表很长,以及熟悉的入站 / 出站 / 路由模型,每一样一张表单。m-ui 更新、也刻意更窄:把 sing-box 内嵌进面板二进制,用线路取代三张配置表,改用户、换上游热换不重启,每次保存用 sing-box 自己的解析器校验,并且从一开始就是一台主机同步任意多台副机。只跑一台服务器、喜欢把配置改得很细,s-ui 是稳妥的选择;跑好几台服务器、整天在改用户,m-ui 就是为此而做的。

选 s-ui,如果

  • 你想要社区更大、教程更多、历史更长的面板。
  • 你喜欢显式地配入站、出站、路由,或者需要 m-ui 没有的协议(ShadowTLS、Naive、TProxy、Redirect)。
  • 你只跑一台服务器,不需要跨机集中配额。

选 m-ui,如果

  • 你有两台以上服务器,希望用户、配额、设备数是一份。
  • 你频繁加减用户,不想每次都重启。
  • 你希望配置错误在进入运行中的内核之前就被拦下,并且自动回滚。
  • 你做分销,需要带额度的独立代理面板。
  • 你想要一个不用 Docker 就能备份、搬迁、更新的二进制。

迁移

m-ui 能导入兼容格式的旧面板数据库,保留端口、凭据与订阅路径,既有客户端不用刷新就能继续用。先拿数据库副本试,看导入报告:它列出映射了什么、跳过了什么。见快速上手。
