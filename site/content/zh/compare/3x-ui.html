m-ui 与 3x-ui

3x-ui 是最流行的 x-ui 系面板,管理的是 Xray-core。m-ui 管理并内嵌的是 sing-box。后面大部分差别都由这一点推出来。事实于 2026-09-05 对照 3x-ui 的 README 与 Releases(v3.7.0,2026-08-24)核对;README 没写明的一律标 未知。

一段话版本

你要的是 Xray —— XTLS Vision 与其它流控、XHTTP、WireGuard 和 TUN 入站、最广的客户端兼容、以及遥遥领先的社区规模 —— 那 3x-ui 是显然的选择,m-ui 不是替代品。你要的是 sing-box(Hysteria2、AnyTLS、TUIC、sing-box 实现的 Reality),并且希望面板内嵌内核、改用户不重启、配置先校验后回滚、一台主机同步多台服务器,那 m-ui 就是你在找的替代方案。

选 3x-ui,如果

  • 你需要 Xray 独有的传输或入站(XHTTP、WireGuard、TUN、MTProto),或者想留在用户已经熟悉的 Xray 生态里。
  • 你看重最大的社区、最多的第三方教程和多年的生产使用。
  • 你要硬件 ID 设备限制或 MTProto —— m-ui 没有这些。

选 m-ui,如果

  • 你已经决定用 sing-box —— 为了 Hysteria2、AnyTLS、TUIC,或只是因为你的客户端都是 sing-box 系。
  • 你有好几台服务器,希望用户表、配额、设备数在所有服务器上是一份,而不是手工克隆入站。
  • 你频繁改用户,不想每次都重启内核。
  • 你希望配置在保存前就由内核自己校验,起不来还能回滚。
  • 你想要一个二进制,不用 Docker,不用单独对内核版本。

迁移

m-ui 不声称能导入 3x-ui 的数据库:导入器只针对一种兼容的旧面板格式,并如实报告映射了什么。从 3x-ui 搬过来意味着重建线路(快速添加几分钟的事),用户要么重建、要么按套餐批量生成;用户凭据会变,客户端需要重新导入一次订阅。先看快速上手。
