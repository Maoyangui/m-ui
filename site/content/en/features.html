Features

What the panel manages, grouped the way the sidebar is. All of it lives in one binary and one SQLite file. On a phone, the lists turn into cards. Help in the top-right corner opens the built-in manual (English and Chinese, with a table of contents and in-page search) at the chapter for the page you are on; in the reseller panel it opens the reseller view.

Lines

A line is inbound protocol + port → exit. Protocols: Hysteria2 (with port hopping and a masquerade site), AnyTLS, TUIC, Trojan, VLESS (Reality / Vision, with a one-click check and suggestions for handshake targets), VMess, Shadowsocks including the 2022 ciphers, plus SOCKS, HTTP and Mixed. Transports: WebSocket, gRPC, HTTPUpgrade, HTTP. Each line can be deployed to all servers or a chosen subset. Turn on rule-based routing to send chosen domain suffixes, full domains, domain keywords, IP ranges or ports to another upstream, direct, or block them; everything else uses the line's upstream. Quick-add presets fill in a free port and sensible options; every save is dry-run through sing-box and port-checked against the panel, other lines and other processes on the box.

Upstreams

Where traffic exits when it should not go direct: VLESS, VMess, Trojan, TUIC, Hysteria2, Shadowsocks and SOCKS outbounds, importable from share links. One-click latency test, scheduled health checks with failure/recovery alerts, and Cloudflare WARP set up from inside the panel. Health is measured on the servers that actually use the upstream: each one checks only what its own lines need, the upstream row shows every server's latency side by side, and alerts name the server that cannot reach it. Changing an upstream hot-swaps the outbound without restarting the data plane. A line can also be an upstream (chained proxy): parameters follow the line, its dedicated credentials do not use a user's quota, and traffic is counted once. Upstream groups use the fastest member that works, switch automatically when it fails, and show which member is in use.

Users

  • Quota, expiry, periodic reset, simultaneous device limit (by source IP: IPv4 addresses and IPv6 /64s counted separately, unioned across servers), upload / download speed limits.
  • Over-quota and expired users are disabled and kicked automatically; the subscription landing page tells them why. Kicking, disabling and re-keying cut QUIC connections (Hysteria2, TUIC) on the spot too: the old connection is closed right away instead of passing traffic for a moment longer.
  • A full device limit only refuses new devices; connected ones are unaffected. Refused connections show up in red under Recent inbound connections on the Dashboard.
  • Bulk create, bulk enable / disable / extend / reset / delete, CSV export, legacy database import.
  • Subscription addresses can be the user name or a random token (setting), and users can generate a temporary share link that you can revoke — revoking cuts the borrower off immediately.
  • Adding, disabling or re-keying a user swaps the inbound user table in place: nobody else is disconnected.

Plans

Templates for quota, duration, devices, speed and line assignment, plus an optional reference price only you see. Apply on create, on renewal or when extending. Users remember their plan, and the Plans page shows how many and who.

From a user's More menu: Renew… adds 1–120 periods at once (enter 3 or 12 to sell a monthly plan quarterly or yearly) as a renewal (usage reset, expiry pushed out), an extension (usage kept) or just assigning the plan; Change plan… offers replace, stack (keep the time left on the old subscription) or prorate by the two plans' reference prices. The dialog previews before and after live, marks changes that cost the user — earlier expiry, instantly over quota — in red and needs a confirmation tick for them; for a single user it carries a de-duplication ID, so a double click or a network retry runs once. Renewing, extending or changing a plan is an explicit activation and also enables users you disabled by hand; the panel tells you first. The user's plan history lists recent renewals and changes.

A plan can tick speed-limit rules that its users, now and later, follow. Resellers get their own plans, separate from yours.

Rules

Temporary speed limits layered on top of a user's own. Schedule: chosen weekdays and a time window in the panel time zone, crossing midnight allowed. Burst: X GB within the last N minutes limits the user for M minutes, lifts automatically and applies again on the next burst; a user can be under several rules at once, each independent. Targets are all users, users of a plan (including ones who get it later), every user of a reseller, or individual users. The master evaluates rules and syncs them to every node; several hits resolve to the strictest, and by default "Cap at the user's own limit" is on, so the result never exceeds the user's own limit. Changes reach live connections immediately, no reconnect needed. The user list shows "Limited"; the landing page never does.

Resellers

Give a reseller a set of lines plus a traffic quota, a device pool, a bandwidth pool and an expiry. Per-user limits are up to the reseller; the pools cap what all of their users can do at the same time. They get their own panel (default port 2054, path /dl) where they create users and plans, set their own landing-page title, notice and contact, and optionally enable two-factor login. All usage rolls up to the reseller; when the reseller is over budget, expired or disabled, every user of theirs is cut off at once. Reseller users are never mixed into your own user list.

Subscriptions

  • Three formats from one address: universal links, Clash / Mihomo YAML, full sing-box JSON. Hand out the plain address; each client gets its own format when it fetches: Clash-family clients (Clash Verge, mihomo, Stash) get Clash, sing-box clients (SFA, SFI) get sing-box, everything else gets universal links. Legacy-core Clash only receives protocols it understands, so SS-2022 and the like are filtered out. Force a format with ?format=clash or ?format=json, or ?format=mihomo for the new core; automatic selection can be switched off in Settings.
  • Every line is listed once per server it is deployed on; assignment can be narrowed to one server's entry (users, plans and reseller grants alike); external nodes and external subscriptions can be merged in; expand an external subscription to see each node's full parameters, test them on every server and from mainland China, add the ones you pick as upstreams, or hide, rename and exclude by keyword (those "official site" and "expires" info nodes); it all survives refreshes.
  • One template each for Clash and sing-box; the panel fills in nodes and groups, and a broken template is refused on save.
  • Browser landing page: usage, expiry, notice, one-tap import for Fotiaoqiang, Clash, Shadowrocket, Nextin, sing-box and Hiddify, QR codes for Clash / universal / sing-box, client download page, temporary sharing.
  • Put your own logo on the landing page: one for the main panel and one per reseller, PNG, JPEG, GIF, WebP or SVG, scaled down and converted to PNG in the browser and live as soon as it is uploaded. When a visitor uses dark mode the logo sits on a light backing; Settings previews both side by side. The logo syncs to nodes with the snapshot and travels with backups.
  • Links in the notice and footer contact, shown as text only: Support (https://t.me/example), [Guide](https://example.com/a), bare addresses, Tg: @username, WhatsApp: +number. Only http(s), tg, mailto and tel links become clickable; the notice holds up to 4000 characters, the contact line 300.
  • Optional traffic-notice node at the top of the list; self-signed certificates automatically add insecure for clients.
  • Dead subscriptions get a short explanation page with your contact details instead of a blank 404.

Servers

One master, any number of nodes. The master pushes lines, upstreams, users and credentials every 5 seconds and pulls back traffic deltas and online IPs; nodes only forward. Per-server traffic ratio, per-server deployment of lines, IPv4 or IPv6 per line on dual-stack servers, connection tracking across servers; scheduled mainland reachability checks from China Mobile, Telecom and Unicom home-broadband probes, with a Telegram alert when a server gets blocked.

IPv6 inbound check: when a server defaults to IPv6, or a line chooses IPv6, the same round has IPv6 probes outside China connect to its IPv6 address and line port, and the result shows on the Servers page and on the line; UDP lines (Hysteria2, TUIC) cannot be probed and say so. Recent inbound connections on the Dashboard lists, per server, who connected and on which line; connections refused by the device limit or a reseller's device pool are in red, and sources that arrived but failed the TLS / REALITY handshake or protocol authentication get their own table with the reason — the first place to look when a user says they cannot connect (a few kinds of failure are never recorded, such as Hysteria2 / TUIC QUIC handshake failures; the note above the table lists them).

See Multi-server.

Certificates

Several per server. Let's Encrypt via HTTP-01, Cloudflare DNS-01 or manual DNS, wildcards included, with DNS and port pre-checks. No domain? Self-sign with one click. Bring your own certificate files too. The line default, panel and subscription each pick their own, and any line can pick its own from a drawer showing which servers have it and how long is left.

Automatic renewal: checked a few minutes after start and then hourly; a certificate is renewed once it enters the last third of its lifetime (30 days left on a 90-day certificate) and hot-reloaded without a restart. Failures retry with 1, 2, 4-hour backoff and notify you on the first failure; the certificate store shows for each certificate whether it renews automatically, the last renewal, the failure count and the next retry, and lets you turn renewal off for one certificate or renew it now. Nodes usually have no notifications of their own, so the master alerts for their failed renewals and expiring certificates. Manual-DNS certificates cannot renew automatically. If the panel, subscription or reseller-panel certificate file cannot be read, a temporary self-signed certificate keeps the service up and a banner tells you, instead of the process refusing to start.

Operations

  • Backup / restore: one zip with the database and certificates (including certificate files outside the data directory that settings point to), scheduled daily backups in the panel time zone, restore from the panel, a migration wizard for moving to a new machine. On restore, a certificate from outside the data directory keeps using the file at its original path if a usable copy of the same certificate is there; otherwise the backed-up copy goes to /etc/m-ui/cert/restored/ and settings are pointed at it. Nothing renews those copies, so the panel says so once at the top and the certificate page marks them: issue or add them again.
  • Kernel tuning, WARP installation and capping the system journal from the Ops page, with logs streamed to the browser.
  • Telegram and webhook: alerts for data plane, upstream and node failures, users about to expire or run out, daily report in your time zone. A Telegram bot lets you look up users, extend, reset traffic, enable or disable and get backups from your phone; it only obeys the chat you set.
  • Update: the panel checks GitHub Releases every 6 hours; one click verifies the checksum, replaces the binary and restarts. Data, certificates and settings are untouched. Nodes update themselves the same way.
  • Logs and audit trail in the panel, each with its own auto-clean retention; the SSH menu (m-ui) for port, path, password and emergency recovery.

Security

Two-factor login (TOTP), login rate limiting per IP, sessions scoped per role, reseller isolation enforced server-side, checksum-verified downloads for the installer and the updater, no telemetry. Config changes never bypass validation.

External API

A token-authenticated HTTP API for creating and updating users, enabling and disabling them, reading usage and fetching subscription links — for shops, bots and automation. Plan operations: /plan (alias /renew) adds N periods, /change switches plans (replace / stack / prorate by reference price), /plan-ops returns the plan history. dryRun previews without changing anything (a shop can quote from it); requestId or an Idempotency-Key header (an order number, say) makes retries run once; a plan change that costs the user returns 409 until you call again with force. Renewals and plan changes enable users who were disabled by hand. Resellers get their own token that only reaches their users and plans. The Admin page lists every endpoint with curl examples filled in with your prefix and token. Documented in docs/API.md.
